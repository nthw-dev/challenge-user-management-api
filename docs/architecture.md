# Architecture

[README](../README.md) · [Checklist](../checklist.md) · [Configuration](configuration.md) · [JWT](jwt-guide.md) · [REST API](rest-api.md) · [gRPC API](grpc-api.md) · [gRPC tooling](grpc.md) · [Testing](testing.md) · [Decisions](design-decisions.md)

One rule: **the core must not know whether a request came over HTTP or gRPC, nor that the data lives in MongoDB.**
Dependencies point inward — adapters → app → domain — and the domain imports only the standard library.
Two things enforce that instead of code review: `depguard` in [`.golangci.yml`](../.golangci.yml) on every lint run,
and [`deps_test.go`](../internal/domain/user/deps_test.go) from inside `go test`.

```
       inbound adapters                core                  outbound adapters
   ┌────────────────────┐                               ┌──────────────────────┐
   │ httpapi (chi)      │──┐                         ┌──│ mongostore.UserRepo  │
   │ grpcapi            │──┼──▶  app (use cases) ────┤  │ mongostore.RefreshRepo
   │ worker (10s tick)  │──┘         ▼                ├──│ security.Bcrypt      │
   └────────────────────┘     domain (User, Email)    ├──│ token.JWT (HS256)    │
            │                                         └──│ clock.System         │
     apierr · bearer · actor        ports live in       └──────────────────────┘
   (shared by both transports)      app/ports.go
```

REST and gRPC are parallel adapters, not one wrapping the other. What they share sits beside them, and is small:

- `apierr` — the one error vocabulary (stable code, safe message, offending fields). Each transport only maps a code to its own status.
- `bearer` — parses `Bearer <token>`.
- `actor` — carries the verified caller's id from the auth layer to the handler, which passes it to the use case as a plain argument.

## Layout

```
cmd/api/                 composition root — the only place that names concrete adapters
  main.go                run(): config → storage → core → metrics → transports → worker → serve
  storage.go core.go     openStorage (connect + indexes), buildCore (ports meet adapters)
  metrics.go servers.go  Prometheus registry + gauge; http.Server timeouts; dev URLs
  lifecycle.go           errgroup of both servers + worker; readiness flip, then drain
  console_dev.go / console_stub.go   /grpcui, only with -tags dev
internal/
  domain/user/           entity, invariants, domain errors — stdlib only
  app/                   use cases + every port (ports.go); types.go, errors.go
    apptest/             fixtures + driving-port fakes shared by every test package
    apptest/mocks/       mockery output (make mocks)
  adapter/inbound/
    apierr/ bearer/ actor/   shared by both transports
    http/    (httpapi)   router, handlers, dto; middleware/ respond/ reqctx/
    grpc/    (grpcapi)   server, services, interceptors, mapper, console; gen/
    grpcconsole/         the grpcui page (-tags dev)
    worker/              counts users on a ticker
    parity/              test-only: same cases through both transports, answers compared
  adapter/outbound/
    mongo/   (mongostore)  client, model, user_repo, refresh_repo — each owns its indexes
    security/ token/ clock/
  platform/              config, logger, id (ULID), netaddr — adapter-free
proto/user/v1/           the gRPC contract
openapi/                 generated by swag from the handler annotations
test/integration/        real MongoDB via testcontainers (build tag): repos, one full journey, concurrency
```

`http/`, `grpc/` and `mongo/` are packages `httpapi`, `grpcapi` and `mongostore`, so importing them never collides with `net/http`, `google.golang.org/grpc` or the driver.
